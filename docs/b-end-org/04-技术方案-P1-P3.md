## 2. 表结构（`V4__org_booking_module.sql`）

- `courts` — 片场挂场馆  
- `teams` — 商户客户球队 + `liaison_staff_id`  
- `team_audit_logs` — 球队变更审计  
- `bookings` — 片场订场；占用态 `BOOKED`/`COMPLETED`；释放 `CANCELLED`/`EXPIRED`  
- `match_results` — 一订场一赛果；home/away 均为本商户球队  

冲突：同 `court_id`，`start < other.end AND end > other.start`，且 `status ∈ {BOOKED, COMPLETED}`。

时段：起止落在半小时；时长 ≥ 30 且为 30 的整数倍。

## 3. API（JWT，`/business`）

### 片场 `/business/courts`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 列表（venueId 可选） |
| GET | `/options` | 在用片场下拉 |
| POST | `/` | 新增 |
| PUT | `/{id}` | 编辑 |
| PUT | `/{id}/status` | 启停 |

### 球队 `/business/teams`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 列表 |
| GET | `/options` | 在用球队 |
| GET | `/{id}` | 详情（含近期订场/战绩/审计） |
| POST | `/` | 新增（对接人必填） |
| PUT | `/{id}` | 编辑基础信息 |
| PUT | `/{id}/liaison` | 换对接人（写审计） |
| PUT | `/{id}/status` | 启停（写审计） |
| GET | `/{id}/audits` | 审计列表 |

### 订场 `/business/bookings`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/calendar` | 日占用格（courtId+date） |
| GET | `/` | 列表 |
| GET | `/{id}` | 详情 |
| POST | `/` | 新建（校验互斥+快照） |
| POST | `/{id}/cancel` | 取消释放 |
| POST | `/{id}/complete` | 标记完成（可录赛果） |

### 赛果 `/business/matches`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 赛果列表 |
| GET | `/ranking` | 球队排行 |
| POST | `/` | 录入（挂 bookingId） |
| PUT | `/{id}` | 修正比分 |

### 业绩（扩展 P0）

`/business/performance/*` 填充 `bookingOperate*` / `bookingLiaison*`（取消/过期不计入；按 `create_time` 归属日）。

订场日历 / 订场列表 / 录赛果 · 片场管理 · 球队管理 · 球队排行榜 · 业绩页订场指标生效。

## 5. 验收要点

1. 同片场重叠第二单失败；取消后可再订  
2. 球队订场：操作员 A + 对接 B → 双业绩各 +1；换对接后旧单仍算 B  
3. 赛果双方须系统球队；排行胜/负/平正确
