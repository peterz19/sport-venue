# 商户组织经营方案（员工账号 · 片场订场 · 球队 · 双业绩）

> 版本：v1.1（最终定稿）  
> 状态：**已锁定**，可作为开发前需求基线；技术拆解另文  
> 范围：B 端为主；C 端订场仅预留边界

---

## 1. 产品目标

把商户从「单账号操作」升级为「组织经营」：

1. **多名员工账号**可登录操作系统  
2. **每次收银 / 订场**都能归因到人，用于员工业绩  
3. **片场 + 半小时**订场，时段互斥占用  
4. **商户侧客户球队**绑定对接员工，订场可展示对接人  
5. 订场后可录**比分战绩**，形成球队胜负排名  

---

## 2. 已确认业务规则（摘要）

| # | 规则 |
|---|------|
| 1 | 球队 = 商户侧客户球队；订场后可录最终比分，后续做胜负排名/战绩 |
| 2 | 球队必须绑定对接员工 |
| 3 | 对接员工可更换；历史场次保留快照 |
| 4 | 球队字段：队名、队长（联系人）、电话、备注 |
| 5 | 订场粒度：场馆下「片场/半场/球场编号」+ 时间 |
| 6 | 时间：半小时起订 |
| 7 | 同片场时间重叠禁止；取消/过期释放占用 |
| 8 | 先 B 端订场；后续 C 端可订，C 端只看个人订场信息 |
| 9 | 订场可选球队或个人（散客） |
| 10 | 订场业绩两套：操作单量 vs 对接单量 |
| 11 | 收银业绩只算操作员工 |
| 12 | 店员可管理球队；变更留审计记录 |
| 13 | 店员只看自己业绩；老板看全部 |
| + | 老板自己收银/订场计入其个人业绩 |
| + | 员工先不限制场馆 |
| + | 权限仅两级：老板 / 店员 |
| + | 赛果双方都必须是系统内球队（保证每队有对接员工） |
| + | 店员可管理商品与片场 |

## 3. 核心对象模型

```text
商户 Merchant
├── 员工账号 Staff（老板 OWNER / 店员 STAFF）
├── 场馆 Venue
│     └── 片场 Court（1号场、2号场、半场A…）
├── 商品 Product（已有收银）
├── 球队 Team（必须对接员工）
├── 销售单 SalesOrder（操作员工）
└── 订场单 Booking
      ├── 片场 + 时段（互斥）
      ├── 预订对象：球队 或 个人
      ├── 操作员工（谁下的单）
      ├── 对接员工快照（若选球队）
      └── 可选：赛果 MatchResult（比分/胜负）
```

### 3.1 两类「人」在订场上的区别（不冲突）

| 角色 | 含义 | 用途 |
|------|------|------|
| **操作员工** | 当前登录并点下「确认订场」的人 | 操作业绩、审计「谁办的」 |
| **对接员工** | 球队长期归属的对接人（下单时快照） | 对接业绩、展示「这队归谁」 |

- 选**个人散客**：只有操作员工，无对接员工  
- 选**球队**：两者都有；可以是同一个人，也可以不同

## 4. 账号与权限

### 4.1 角色

| 角色 | 产品名 | 能力 |
|------|--------|------|
| OWNER | 老板 | 员工管理、全店业绩、全部配置、球队/订场/收银 |
| STAFF | 店员 | 收银、订场、球队管理（有审计）、**仅自己的业绩** |

### 4.2 登录主体

- 每个人一个账号（老板也是账号）  
- 登录后所有写操作自动带 `operator_id`  
- 停用员工：不能登录；历史单据保留  

### 4.3 权限矩阵（Phase 1）

| 功能 | 老板 | 店员 |
|------|:----:|:----:|
| 员工账号增删改/停用/重置密码 | ✅ | ❌ |
| 商品管理 | ✅ | ✅ |
| 收银 | ✅ | ✅ |
| 片场管理 | ✅ | ✅ |
| 订场 / 取消订场 | ✅ | ✅ |
| 录比分 | ✅ | ✅ |
| 球队管理 | ✅ | ✅（变更写审计） |
| 改球队对接人 | ✅ | ✅（写审计） |
| 员工账号管理 | ✅ | ❌ |
| 看全店员工业绩 | ✅ | ❌ |
| 看自己业绩 | ✅ | ✅ |
| 销售/订场全店报表 | ✅ | ❌（店员看自己相关明细/业绩） |

## 5. 片场与订场互斥

### 5.1 片场（Court）

挂在场馆下，例如：

- 篮球馆 → 1号全场 / 2号全场 / 半场A / 半场B  
- 字段建议：所属场馆、名称、编号、类型（全场/半场等）、状态、排序、备注  

员工暂不绑场馆/片场，可订商户下任意可用片场。

### 5.2 时间规则

- **最小单位：30 分钟**  
- 起订至少 30 分钟  
- 建议按半小时网格展示（如 18:00–18:30、18:30–19:00）  
- 下单可选连续多格（如 18:00–19:30 = 3 格）

### 5.3 冲突与释放

```text
同一 court_id + 时间区间有交集
且原单状态 ∈ {已预订, 进行中}（名称可再定）
→ 禁止新单

取消 / 过期（到点未用或系统过期策略）→ 释放占用
```

展示上：日历/网格中已占用格标红或灰，不可点。

### 5.4 订场对象

| 类型 | 必填 | 对接员工 |
|------|------|----------|
| 球队订场 | 选球队 | 下单时写入球队当前对接人**快照** |
| 个人订场 | 联系人姓名/电话（散客） | 无 |

B 端下单流程建议：

1. 选场馆 → 选片场 → 选日期时段  
2. 选「球队」或「个人」  
3. 若球队：展示对接员工（只读，来自球队）  
4. 确认 → 写操作员工 = 当前登录人

## 6. 球队与战绩

### 6.1 球队字段（最小集）

- 队名  
- 队长（联系人）  
- 电话  
- 备注  
- **对接员工（必填）**  
- 所属商户  
- 状态（启用/停用）

### 6.2 对接人变更

- 可更换对接员工  
- **历史订场单保留当时的对接人快照**，排名与历史业绩不被改写  
- 每次变更写入审计：谁改、何时、从谁改到谁、可选原因  

### 6.3 球队审计（店员也可改，但留痕）

至少记录：

- 创建 / 编辑基础信息 / 更换对接人 / 停用  
- 操作人、时间、变更前后摘要  

### 6.4 赛果与排名

订场完成后（或比赛结束后）可录入：

- **必须关联订场单**  
- **主队、客队都必须是系统内已录入球队**（因而双方都有对接员工）  
- 主队比分、客队比分  
- 胜/负/平（可由比分自动计算，平局允许）  
- 备注  

规则补充：

- 同一订场单赛果以一报为准（可允许老板/店员修正，修正写审计）  
- 排名仅统计「已录入有效赛果」的场次  
- 换对接人不回溯改历史赛果上的对接快照（若赛果需展示对接人，用订场快照）  

衍生展示：

- 球队战绩列表（胜-负-平、进球/失球或得分差等）  
- 商户维度胜负排名榜

## 7. 业绩口径

### 7.1 收银

| 指标 | 归因 |
|------|------|
| 销售笔数 / 销售额 | **仅操作员工** |

（老板自己收银算老板。）

### 7.2 订场（两套并行）

| 指标 | 归因 | 说明 |
|------|------|------|
| 操作单量 / 操作订场金额 | 操作员工 | 谁下的单 |
| 对接单量 / 对接订场金额 | 对接员工快照 | 仅球队订场；个人订场不计入对接业绩 |

同一张球队订场单可以同时：

- +1 到操作员的「操作订场」  
- +1 到对接人的「对接订场」  

### 7.3 谁能看什么

| 角色 | 业绩视图 |
|------|----------|
| 店员 | 仅自己的收银 + 自己的操作订场 + 自己的对接订场 |
| 老板 | 全员排行 + 下钻某人明细 |

## 10. 关键页面流程（简述）

### 10.1 员工管理（老板）

- 列表：姓名、账号、角色、状态  
- 新增员工、停用、重置密码  
- 不可删除有历史单据的账号（或仅停用）

### 10.2 球队管理

- 新增：队名、队长、电话、备注、对接员工（必选）  
- 编辑：变更写审计  
- 详情：基本信息 + 近期订场 + 战绩摘要  

### 10.3 订场

- 日历：按片场看半小时格占用  
- 新建：互斥校验失败明确提示「与某某订单冲突」  
- 详情：预订对象、操作人、对接人（快照）、状态、赛果入口  

### 10.4 业绩

- 店员：我的今日/本月（收银 | 操作订场 | 对接订场）  
- 老板：员工排行表 + 下钻

## 11. 状态建议

### 订场单

`PENDING`（可选）→ `BOOKED`（占用中）→ `COMPLETED`（已完成/可录赛果） / `CANCELLED`（释放） / `EXPIRED`（释放）

占用中的状态集合：`BOOKED`（及若有的 `IN_PROGRESS`）

### 球队

`ACTIVE` / `INACTIVE`

### 员工账号

`ACTIVE` / `DISABLED`

## 12. 分期建议

| 阶段 | 内容 |
|------|------|
| **P0 账号** | 员工管理、老板/店员登录隔离、收银继续归因操作人、按员工收银业绩 |
| **P1 片场订场** | 片场 CRUD、半小时网格、互斥占用、B 端订场（球队/个人）、操作人+对接人快照 |
| **P2 球队与审计** | 球队必绑对接人、换人快照、变更审计日志 |
| **P3 赛果排名** | 录比分、球队战绩与排行榜 |
| **P4 C 端** | 个人订场、仅个人可见 |

可与现有收银并行：P0 可尽快叠在当前商户端上。

## 13. 最终定稿摘要

> 商户下多员工（老板/店员）登录经营；收银只算操作人；订场按片场+半小时互斥；可选球队或个人；球队必有对接人且历史快照；订场同时统计操作业绩与对接业绩；店员可管商品/片场/球队（球队变更审计）、只看自己业绩；老板管员工且看全部；赛果双方必须为系统内球队；C 端订场预留且仅展示个人订场信息。
