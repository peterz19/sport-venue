# 运维手册 · 本地部署与排错

> 更新：2026-07-28  
> 面向开发/实施：在本机跑通 **venue + merchant + admin + MySQL + Redis**，并验证 SaaS 主链路。

---

## 1. 环境要求

| 项 | 建议 |
|----|------|
| JDK | **21**（勿用过高版本，以免 Lombok 编译失败） |
| Maven | 3.8+ |
| Node.js | 18+（商户端 / Admin） |
| MySQL | 8.x，库名 `sport_venue` |
| Redis | 本地可用（venue 依赖） |

本机若用 Homebrew OpenJDK 21：

```bash
export JAVA_HOME=/opt/homebrew/Cellar/openjdk@21/21.0.7/libexec/openjdk.jdk/Contents/Home
export PATH="$JAVA_HOME/bin:$PATH"
```

（版本号以本机 Cellar 实际路径为准。）

- 平台管理员：`admin` / `123456`（需库中已有 ADMIN 用户；可用 `/auth/dev/reset-admin-password` 重置，**仅开发**）。  
- 订场/片场需要该商户下已有 `venues` 记录。

## 3. 启动服务

### 3.1 场馆服务（后端）

```bash
export JAVA_HOME=...   # JDK 21
cd sport-venue-venue
mvn spring-boot:run -Dspring-boot.run.profiles=local -DskipTests
```

健康检查：

```bash
curl -s http://localhost:8082/api/health
```

期望：HTTP 200，JSON 中 `status=UP`。

Swagger（开发）：`http://localhost:8082/api/swagger-ui/index.html`（以实际为准）。

**SaaS 本地配置**（`application-local.yml` 已含）：

| 项 | 含义 |
|----|------|
| `saas.wx.mock-enabled=true` | C 登录不调微信，`openid=mock_{code}` |
| `saas.crypto.key` | 微信 Secret 等 AES 加密密钥 |
| `saas.booking.expire-delay-ms` | 订场过期任务间隔（默认 300000） |

### 3.2 商户前端

```bash
cd sport-venue-merchant
npm install   # 首次
npm run dev
```

访问：http://localhost:3001  
代理：`/api` → `http://localhost:8082`。

### 3.3 平台 Admin

```bash
cd sport-venue-admin
npm install   # 首次
npm run dev
```

访问：http://localhost:3000  
使用 `admin` / `123456` 登录（非 ADMIN 会被拒绝）。

### 3.4 端口占用

```bash
lsof -ti :8082 | xargs kill -9   # 慎用
lsof -ti :3000 | xargs kill -9
lsof -ti :3001 | xargs kill -9
```

## 4. 冒烟检查

### 4.1 一键 SaaS 冒烟（推荐）

服务启动后：

```bash
bash scripts/saas_smoke.sh
```

覆盖：健康检查、Admin/商户登录、商户调平台接口 403、开户+首场馆、绑小程序、C 登录/充值、停用后登录 `40301`。  
期望：`pass=14 fail=0`。

### 4.2 B 端业务清单

1. 老板登录商户端，顶栏显示「老板」  
2. 商品 → 收银台现金支付 → 销售报表有数据  
3. 新建店员 → 店员登录 → 无员工管理  
4. 建片场 → 订场日历 → 重叠拒绝 → 取消后再订  
5. 球队订场 → 换对接人 → 历史快照不变  
6. 录赛果 → 排行榜变化  
7. 「我的业绩」有收银与订场指标  

### 4.3 平台 / C 端手工抽查

1. Admin 开户（可填首场馆）→ 新老板可登录商户端  
2. 商户详情：打开 C 端开关 → 绑定小程序 AppId/Secret  
3. `POST /c/auth/wx-login` 带该 `appId` → 拿到 C token → 充值看余额  
4. 停用商户 → 老板登录失败文案/码 `40301`  

操作细节见：`操作手册-商户端.md`、`操作手册-平台Admin.md`。

## 5. 日志与排错

| 问题 | 排查 |
|------|------|
| 编译失败（Lombok） | 确认 `java -version` 为 21 |
| Config Server Connection refused | local 可忽略，只要最终 `Started VenueApplication` |
| 商户登录「商户已停用」 | Admin 将该商户状态改回 `ACTIVE` |
| 商户调 `/merchants` 得 403 | **预期**：平台接口仅 ADMIN |
| C 登录失败「未配置的小程序」 | Admin 先绑 `MINI_PROGRAM` 且开关 `enableCEnd` |
| C 功能 40303 | 打开商户 `enableCEnd` / `enableBooking` / `enableRecharge` |
| 401 | 清 `localStorage`（商户 `merchantInfo` / Admin `token`）后重登 |
| 订场冲突异常 | 查是否仍有 `BOOKED/COMPLETED` 占用；`EXPIRED` 不应占场 |
| 前端请求失败 | 先 `curl` 8082 `/api/health`；看 Network 的 `/api/...` |

后端日志：运行 `mvn spring-boot:run` 的终端（或 `/tmp/venue-saas*.log` 若自行重定向）。
